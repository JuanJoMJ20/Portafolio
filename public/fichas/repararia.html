01

Qué es

Cuando algo se daña en casa, lo normal es buscar en internet un tutorial genérico sin saber si el problema es seguro de tocar o no. RepararIA invierte ese orden: analiza tu caso primero.

Antes

Algo falla → buscas en YouTube un tutorial que no es tu caso → no sabes si es peligroso → lo intentas a ciegas.

→

RepararIA

Apuntas la cámara o describes el problema con tu voz → la IA diagnostica tu caso puntual → pasos claros, o alerta si hay riesgo real.

02

Para qué sirve

📷

Diagnóstico por foto

Gemini analiza la imagen de la falla y responde en un JSON con la misma forma que usa toda la interfaz — no es un mock.

🎙️

Diagnóstico por voz

Grabas tu descripción hablada del problema y Gemini la transcribe y diagnostica — en vez de fingir que "escucha" la falla mecánica.

⚡

Modo crítico automático

Si hay riesgo real (eléctrico, incendio, gas), la interfaz entera cambia de tono — colores, botones, tab bar — sin recargar nada.

🗂️

Historial persistente

Cada diagnóstico resuelto queda guardado en tu cuenta (Supabase), con opción de revisarlo o borrarlo cuando quieras.

🔧

Pedir un técnico

Flujo de solicitud con mapa estilizado y confirmación — simulado a propósito, no hay despacho real todavía.

!

Errores humanizados

Todo aviso del sistema explica qué pasó, por qué, y qué hacer ahora — nunca un código de error crudo.

03

Parte técnica

Plataforma
React Native + Expo (SDK 58) — Android e iOS desde un solo código, compilado a APK con EAS Build
Navegación
React Navigation — native-stack para auth/modal de error, bottom-tabs con barra flotante tipo glass hecha a medida
Backend
Supabase — Auth (login/registro/recuperar contraseña) + Postgres con Row Level Security por usuario en history y maintenance_reminders
IA generativa
gemini-3.5-flash-lite con fallback a gemini-3.1-flash-lite — visión para fotos, comprensión de audio para voz, salida JSON forzada por schema (mismo contrato para ambos casos)
Captura
expo-camera (vista en vivo + congelado al disparar) y expo-audio con metering en vivo para un visualizador de voz reactivo de verdad
Diseño
Sistema propio con tokens de color, expo-linear-gradient, expo-blur, animaciones con Animated (scan-line, pulso, stagger-in) y lucide-react-native para íconos
Onboarding
3 slides la primera vez que se abre la app, guardado con AsyncStorage para no repetirse

El audio no "escucha" la falla — transcribe tu voz

No existe un modelo confiable para detectar una falla mecánica solo por el patrón de sonido. En vez de simularlo, se pide describir el problema en voz alta y Gemini lo diagnostica como si fuera texto.

Nunca mezclar animación JS con animación nativa

Un mismo Animated.View no puede tener un color animado por JS (useNativeDriver:false) junto a transformaciones nativas — causaba crashes reales. Se resolvió separando esas capas en componentes aparte.

"Calmar la alerta" nunca toca el contenido, solo el tono

Un diagnóstico peligroso no se puede marcar como "resuelto" solo porque se calmó el color de la pantalla — badge y contenido reflejan el riesgo real; el botón de calma solo afecta el acento visual global.

El cliente de Supabase no puede tronar si faltan las env vars

createClient() lanza una excepción si la URL viene vacía — eso tumbaría la app entera en un build sin las variables configuradas. Se blindó con una URL de relleno para fallar en gris, no en crash.

●

Nota de privacidad: la API key de Gemini viaja embebida en el cliente porque es un proyecto de materia sin backend propio todavía — antes de publicarlo en serio, iría detrás de una Edge Function. Las fotos y audios solo se envían a Gemini para el diagnóstico puntual; lo único que se guarda en Supabase es el resultado (texto), nunca el archivo original.
